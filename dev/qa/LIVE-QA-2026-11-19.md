## Confirmed issues, in recommended fix order

### QA-LIVE-01 — Classic Mac menu bar is covered (high)

1. Connect in any supported era.
2. Appearance → Classic Mac OS → OK; reload and enter the desktop.
3. Try the clock, network status or the top menu bar.

The desktop covers the menu bar. Clock/network elements have valid top-of-screen rectangles, but hit testing returns `retro-desktop` instead of the control. Screenshot review confirms the entire bar is absent visually. Their clicks do not open the expected dialogs. Aqua works correctly; it has no bottom taskbar and exposes these controls at the top.

Expected: Classic Mac's menu bar and its controls remain visible and clickable above the desktop. Reproduced at both tested sizes. Evidence: `flash-classic.jpg`; hit-test results in JSON `chrome`.

### QA-LIVE-02 — Archive HTTP error pages are treated as loaded (high)

1. Open Yahoo! Directory in WebThen (also observed with other archive destinations).
2. Wait for the Wayback request to finish.

Wayback returned a visible **429 Too Many Requests / nginx** page. WebThen displayed it in the iframe, removed its loading context and reported **Done**. This violates the intended period failure screen for failed archive loads. The external rate limit is a provider failure; treating its error response as a successful page is the WebThen handling issue.

The iframe URL correctly used `20030623120032if_/`; Archive Properties retained the plain replay URL without `if_`. The publisher-hosted Longmont interview instead reached WebThen's **The page cannot be displayed** screen with **Open original interview**, showing that the existing network-failure fallback does work for that failure path.

Expected: failed HTTP replay pages should show a useful period error and preserve Open archive; don't report Done for a recognized error. Cross-origin constraints need to be considered when designing the fix. Evidence: `archive-429.jpg`.

### QA-LIVE-03 — Tour's Show Appearance action does not open Appearance (medium)

1. Appearance → Replay quick tour.
2. Next twice to **Choose your desktop’s appearance**.
3. Select **Show Appearance**.

The desktop is shown, but the Appearance dialog remains closed. The action currently activates Desktop rather than settings. The spotlight is present, and all tour steps fit without scrolling, but this action does not do what its label promises.

Expected: open Appearance, keeping the tour usable when the dialog closes.

### QA-LIVE-04 — Disabling the modem recording retains a connection delay (medium)

1. In 2002–2004, open Connect To and choose Dial-up.
2. Uncheck **Play modem recording** and select Connect.

The dialog remains visible and runs a silent connection sequence for approximately **5,183 ms**. Tom previously requested immediate entry when this option is unchecked. Broadband does enter briefly and quietly; this finding concerns silent Dial-up.

Expected under that earlier preference: no simulated delay when the recording option is off. The later period-sequence implementation currently explicitly uses a five-second silent Dial-up sequence, so the fix should reconcile these two behaviors without changing the recorded connection.

## Privacy, errors and limitations

- Fresh cookie-free HTTPS requests to **webthen.org**, the branch alias and immutable deployment address each returned **302 to Cloudflare Access**, with no desktop content returned. Normal certificate verification was used. The existing approved browser session could enter the app. No Access settings or memberships were changed. Fresh OTP delivery and a non-approved email rejection were not repeated; no tester was emailed during QA.
- Authenticated visits to `/dev/`, `/VERIFICATION.md`, `/contents/server.cjs` displayed **Not found**. Raw authenticated status codes were not captured.
- No WebThen-origin error-level console message was captured during this run. One provider exception was captured during Alien Hominid: `TypeError: Cannot read properties of null (reading 'categories')`, from `archive.org/includes/build/js/emulation.min.js` / its Sentry wrapper. Therefore the whole-session console is **not error-free**.
- Wayback rate limiting prevented successful historical page reading in the sampled replays. Do not interpret toolbar success or correct URLs as archive content verification. This was not a fresh verification of all 352 Directory destinations, and repeated bulk archive requests were avoided after 429 responses.
- Immersive fullscreen was refused by the in-app browser; WebThen displayed its fallback message. Escape was exercised with no fullscreen active, so actual fullscreen entry/exit requires a regular-browser check. This is not classified as a WebThen defect from this evidence.
- Chromium/IAB only. Firefox, Safari, mobile/touch, screen readers, a full keyboard audit, physical sound output, exact provider response statuses, long sessions, all personal/archived chat messages and full game completion remain unverified.
- Preferences changed for testing were restored to the 2003 era, XP, Broadband, modem option enabled, 56k off, ThenAmp paused at 1.5× with Midnight skin and random screen names. Temporary viewport override was removed; QA tabs were closed.
